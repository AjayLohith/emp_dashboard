# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | Global / lines 22-23 | Hard-coded fallback connection URI (`"mongodb://localhost:27017"`) and DB name (`"attendance_db"`) mask missing environment variables; naive timezone handling. | App connects to fallback if env vars unset; datetimes return timezone-naive, causing local-vs-UTC drift. | Read strictly from `MONGO_URI` and `MONGO_DB` without hard-coded fallbacks; configure `tz_aware=True` and server selection timeouts on MongoClient. |
| 2 | `health` / lines 72-74 | Returns `{"status": "ok"}` unconditionally without verifying MongoDB connectivity or index readiness. | Route returns HTTP 200 even when MongoDB is offline. | Pings MongoDB via `db.command("ping")` and verifies startup index initialization; returns HTTP 503 if unavailable. |
| 3 | `compute_late_minutes` / lines 33-37 | Replaces hour/minute directly on UTC/naive `punch_in` using IST shift string; compares integer minutes (`minutes > 10`), ignoring seconds; ignores overnight shifts. | For shift `09:30`, punch-in at `09:40:01` IST yields 0 instead of 10 late minutes; UTC replace corrupts time by 5.5 hours. | Convert UTC to IST; check `diff_seconds > 600` (strict 10-minute grace period); anchor start date correctly across overnight shifts; compute `floor(diff_seconds / 60)`. |
| 4 | `compute_work_hours` / lines 40-41 | Uses Python's built-in `round()`, which applies banker's rounding (round half to even) rather than decimal half-up. | Durations rounding at 0.005 boundaries (e.g. 2.675 hours) produce 2.67 instead of 2.68. | Use `Decimal.quantize(Decimal('0.01'), rounding=ROUND_HALF_UP)`. |
| 5 | `compute_overtime` / lines 44-47 | Does not enforce 30-minute minimum threshold (R3); sets `shift_end` on punch date rather than shift start + 1 day for overnight shifts. | Punch-out 15 minutes after shift end stores 15 minutes overtime instead of 0; overnight shift end calculation fails. | Enforce minimum 30-minute duration (`diff_minutes >= 30`); calculate correct overnight shift-end instant on following calendar day. |
| 6 | Models `EmployeeIn`, `PunchInIn` / lines 53-67 | Missing OpenAPI validation constraints; accepts unconstrained types; loose type coercion. | Invalid `emp_code` (e.g. `"BAD123"`), equal shift start/end, or non-numeric/string timestamps are accepted rather than returning 422. | Added regex `^EMP\d{4,6}$`, string length bounds, calendar date parsing, `shift_start != shift_end` validator, and strict epoch ms validation with `mode="before"`. |
| 7 | `create_employee` / lines 78-85 | Check-then-insert race condition; `created_at` uses local un-truncated `datetime.now()` and returns BSON/datetime object. | Concurrent duplicate employee creations both succeed or crash; response `created_at` is an ISO string instead of epoch milliseconds. | Add database unique index on `emp_code`; catch `DuplicateKeyError` returning HTTP 409; truncate server UTC instant to whole seconds and return integer epoch ms. |
| 8 | `list_employees` / lines 88-97 | Offset calculation bug `skip = page * page_size`; `total` counts unfiltered collection; missing sort. | Page 1 skips the first 20 records; `total` returns collection size rather than filtered count; results unordered. | Correct skip to `(page - 1) * page_size`; set `total = count_documents(q)`; sort by `emp_code` ascending in MongoDB. |
| 9 | `punch_in` / lines 100-122 | Missing employee existence check; check-then-insert race; naive datetime conversion; invents response `"id"` field. | Unknown employee triggers unhandled `TypeError` (500); concurrent requests insert duplicate attendance logs; response leaks MongoDB `_id` as `"id"`. | Check employee exists (404); create compound unique index `(emp_code, date)` and handle `DuplicateKeyError` (409); convert epoch ms to UTC; remove `_id`/`id` from response. |
| 10 | `list_attendance` / lines 124-151 | Loads entire collection into Python memory (`list(find())`) and sorts in Python; sort order misses secondary key; invents `"id"`. | OOM and massive latency on 100,000 documents; sort misses `emp_code` tie-breaker; leaks `"id"`. | Execute query, compound sort `[("date", -1), ("emp_code", 1)]`, count, and pagination skip/limit directly in MongoDB; strip `_id`. |
| 11 | Entire app / line 154 | Missing 7 required endpoints: `POST /attendance/punch-out`, `PATCH /attendance/{emp_code}/{date}`, and all analytics/explain routes; no startup index creation. | Any call to punch-out, regularization, analytics, or admin explain returns 404 or 405; database has no indexes. | Implemented all endpoints per OpenAPI contract, with atomic conditional operations, MongoDB aggregations, and startup index initialization. |

### Inspected and Decided Not a Defect

1. **Synchronous route definitions (`def`)**: Using standard synchronous `def` endpoints with synchronous PyMongo is appropriate and intended by FastAPI, as FastAPI executes synchronous handlers in the AnyIO thread pool without blocking the async event loop.
2. **FastAPI exception response shape `{"detail": ...}`**: FastAPI's default error body matches the OpenAPI `Error` (`{"detail": "..."}`) and `ValidationError` (`{"detail": [...]}`) schema specifications.
3. **Pydantic for schema validation**: Using Pydantic v2 models provides contract enforcement and OpenAPI schema parity without extra overhead.
